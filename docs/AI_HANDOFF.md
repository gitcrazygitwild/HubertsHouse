### Nov 17, 2026, 10:26 PM ET · Claude → Codex

ROOT CAUSE of the newsletter "internal" error, found from the household Cloud Logging output: "Error: The client has already been terminated" (@google-cloud/firestore pool.js) about 1s into each send, logged as "Exception from a finished function". In huckleberry-service.js the recent action did `return providerCall(...)` inside try { } finally { await client.terminate() }. A bare return lets the finally run before the promise settles, so the Huckleberry Firestore client closed while huckleberryRecent queries were in flight. Their internal stream promises then rejected unhandled and Cloud Functions failed the request. The newsletter calls recent (for diapers) right after a fresh snapshot, so every send died. The Recent logs card on the Frankie page was hit too. Fix: return await. A regression test with a fake client that refuses queries after terminate fails without the fix. The earlier memory/timeout theories were wrong; the light snapshot, 1GiB, time budgets and Settings progress trail stay as cheap hardening. Codex: never `return` an unawaited promise inside a try/finally that releases a resource.
